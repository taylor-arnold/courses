The exam is 75 minutes. There are 6 tasks (labeled A–F), each presenting a block of Python code, with 12 total questions (typically 2 per task). You will need to read code, trace through it, explain what it does and interpret results in context. You will not need to write code yourself.

Creating Point Geometries and Projections (Task A)

You should understand what DSGeo.from_latlon() does: given a DataFrame with lon and lat columns, it adds a new column called geometry that stores each point as a binary-encoded geometric object. This column enables spatial operations that plain numeric coordinates cannot support.

You also need to understand coordinate reference systems (CRS). A CRS defines how coordinates on Earth’s curved surface are projected onto a flat map. Key points:

  • Different regions have different appropriate projections. A projection designed for France (like EPSG:2154) will produce an accurate, familiar-looking map of French data. Using a generic unprojected system (WGS 84 / EPSG:4326) instead would show distortion, particularly in the shapes and relative spacing of points, because raw latitude/longitude treats the curved Earth as if it were flat.
  • You do not need to memorize EPSG codes, but you should understand why a projection would be preferred over raw latitude and longitude.

Spatial Joins (Task B)

You need to understand DSGeo.sjoin():

  • Argument order matters. DSGeo.sjoin(metro, state) (points first, polygons second) keeps the point geometry in the output and matches each metro area to the state containing it, roughly one row per metro area. DSGeo.sjoin(state, metro) (polygons first, points second) keeps the polygon geometry and produces more rows because each state is duplicated for every metro area it contains. This is analogous to a one-to-many join.
  • Self-joins with predicates. DSGeo.sjoin(state, state, predicate="touches") finds all pairs of states sharing a boundary. The result does not have exactly 50 rows (one per state). It has one row per pair of neighboring states, and each border appears twice (California touches Oregon and Oregon touches California), so the row count depends on the total number of shared borders in the country.

Area, Unit Conversion, and Choropleth Maps (Task C)

You should understand:

  • DSGeo.add_area(state, crs=5069) computes each polygon’s area using a projected CRS. The result is in square meters (the default unit). To get square kilometers, you divide by 1,000,000.
  • Choropleth maps color regions by a variable’s value. The key interpretive pitfall: large geographic regions (like Alaska or Montana) dominate the viewer’s attention simply because they take up more visual space. This makes choropleths misleading for raw counts like total population, a huge but sparsely populated state would appear visually dominant. Variables that are rates or densities (like population per square kilometer) avoid this distortion because they are already normalized by area.

Fractional Years vs. Date Objects (Task D)

You should be able to compare these two approaches for plotting data over time:

  • Fractional year (year + (month - 1) / 12 + (day - 1) / (12 * 31)): converts a date into an ordinary number. Advantage: works regardless of whether the data is sorted or has missing values, and can be plugged directly into models or calculations. Disadvantage: the x-axis labels are decimal numbers (like 2023.48), which are not human-readable dates.
  • Date objects (pl.date(c.year, c.month, c.day)): creates a proper Date column. Advantage: plotnine automatically produces readable date labels on the axis. Also unlocks the .dt namespace for component extraction. For example, we need a Data column fro extracting the day of the week. Disadvantage: requires properly formatted date data.

Window Functions: .shift() and .over() (Task E)

You need to understand:

  • What .shift(n) does: shifts all values in a column by n rows. .shift(1) gives the previous row’s value. .shift(2) gives the value from two rows back.
  • The boundary-crossing bug: without .over(), .shift() operates on the entire DataFrame. If data is sorted by page then datetime, the first row of page “Beta” will incorrectly pull its shift(1) value from the last row of the previous page “Alpha.” This produces a meaningless size_diff. If we use .over, the shift will correctly produces null values at the boundaries.
  • Application to Wikipedia: Using the code c.size.shift(2).over(c.page) applied to the page edit data retrieves the page size from two edits ago within the same page. If the current size equals the size from two edits ago, it means the middle edit was likely undone. The page was changed and then changed back, which is a reversion.

Filtering Edge Lists with Semi Joins and Centrality Measures (Task F)

You need to understand the two-step semi join pattern for restricting a citation network to a subset of nodes:

  • The table with the original edgues should have doc_id and doc_id2. We need to keep only edges where both endpoints. We can do this with a combination of two semijoins
  • Why both are necessary: if you only do the first, you retain edges that point out to cases not in your subset. Those external cases would then appear as nodes in the network even though they don’t belong to the filtered topic.

You should also understand the difference between the following two metrics well enough to interpret a specific scenario:

  • Degree: a simple count of how many edges a node has (i.e., how many direct neighbors).
  • Betweenness centrality: measures how often a node lies on the shortest path between other pairs of nodes.

The key insight for the exam: a node with low degree but very high betweenness is a bridge. It doesn’t have many direct connections, but it sits at a critical juncture between different parts of the network. Without it, other nodes would need many more hops to reach each other. In the Supreme Court context, such a case might be the key precedent linking two otherwise separate lines of legal reasoning.
