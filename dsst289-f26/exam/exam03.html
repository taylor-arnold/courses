The third exam consists of 15 questions in the same style as the first two exams: hand-written code blocks, this time concerning the four RVA flights tables described below. You should generally be comfortable with the material in Chapter 7, Chapter 8, Chapter 9, and Chapter 10. However, only those items mentioned below, along with everything listed on Exams I and II, will be required for this exam.

The questions all concern the four RVA flights tables. The first, rva, has one row for each flight, with the columns year, month, day, dep_time, sched_dep_time, dep_delay, arr_time, sched_arr_time, arr_delay, carrier, flight, tailnum, origin, dest, air_time, and distance. The second, airport, has one row for each airport, with the columns faa, name, lat, lon, alt, and tzone. The third, airline, has one row for each airline, with the columns carrier and name. The fourth, plane, has one row for each aircraft, with the columns tailnum, year, manufacturer, model, engines, and seats.

  1. Building a bar plot with geom_bar, which counts the rows in each category for you, and with geom_col, which draws a number you have already computed. You should be able to say which one a given task calls for and why.
  2. Ordering the categories of a plot by sorting the data before piping it into plotnine, including sorting by a window aggregate such as .sort(pl.len().over(c.col)) or a median .over the category, and treating a numeric column as a category by casting it to a string with .cast(pl.String).
  3. Building a histogram with geom_histogram, setting either binwidth or bins, and being able to say what the height of a single bar means. You should also know geom_density and its adjust option.
  4. Building a boxplot with geom_boxplot, and writing the .group_by and .agg code that computes by hand the three numbers that make up each box.
  5. Adding a line of best fit with geom_smooth(method="lm", se=False).
  6. Flipping the axes of a plot with coord_flip.
  7. Changing the scale of a plot by adding scale_x_log10, scale_y_log10, scale_color_cmap_d, or scale_size_area. You should also know how to assign a specific color to each category with scale_color_manual, and how to pin the start of an axis with the limits option of scale_x_continuous or scale_y_continuous. You do not need to know how to set the breaks manually.
  8. Splitting a plot into a grid of small panels with facet_wrap.
  9. Labeling a plot with labs, including the x, y, color, title, subtitle, and caption arguments.
  10. Identifying the primary key of a table and the foreign keys that point to it, and checking whether a column really is a primary key by comparing .n_unique() against len().
  11. Combining two datasets using .join, where the key may have multiple columns (on=[c.key1, c.key2]) or different names in the two tables (left_on and right_on). You should be able to say which table belongs on the left and why, and to use suffix when joining the same table twice.
  12. Changing the type of a join with how="left", and saying what an inner join does with rows that have no match.
  13. Using the filtering joins how="semi" and how="anti", and saying what a row returned by an anti-join tells you about your data.
  14. Reshaping a table with .pivot(index=, on=, values=) and .unpivot(index=, variable_name=, value_name=), and explaining why plotnine usually needs the long version.
  15. Splitting a packed cell with .str.split and unraveling the result with .explode.
  16. We will not have .join_asof or .join_where on this exam.

Many questions will require putting multiple functions together in a method chain. All can be done with at most three data methods and three graphics methods. Your code should follow the class formatting rules of putting parentheses around the whole block, starting with the DataFrame, and having each method on its own line.

Practice Exam Questions and Answers

The questions below use the movie dataset from the earlier study guides, with columns year, title, mpa, runtime, gross, rating_count, rating, and metacritic. They also use a second table, people, with one row for each person who worked on a film and the columns year, title, role (either "director" or "starring"), person, and gender.

1. Create a horizontal bar plot of the number of films with each MPA rating, letting plotnine do the counting for you, with the bars ordered from the most common rating to the least.

(
    movie
    .sort(pl.len().over(c.mpa), descending=True)
    .ggplot(aes(c.mpa))
    .geom_bar()
    .coord_flip()
)

2. Create a histogram of the runtimes of the films, using a bin width of ten minutes. What does the height of a single bar tell us?

# The height of the bar spanning 90 to 100 is the number of films in the
# dataset whose runtime falls between 90 and 100 minutes.
(
    movie
    .ggplot(aes(c.runtime))
    .geom_histogram(binwidth=10, boundary=0)
)

3. Create a boxplot showing the rating of the films for each MPA rating, with the categories ordered by rating and the boxes running horizontally. Then write the code that computes by hand the three numbers that make up each box.

(
    movie
    .sort(c.rating.median().over(c.mpa))
    .ggplot(aes(c.mpa, c.rating))
    .geom_boxplot()
    .coord_flip()
)

(
    movie
    .group_by(c.mpa)
    .agg(
        q25 = c.rating.quantile(0.25),
        q50 = c.rating.quantile(0.50),
        q75 = c.rating.quantile(0.75)
    )
)

4. Create a scatterplot of the number of ratings on the x-axis and the gross on the y-axis, with both axes on a logarithmic scale and a straight line of best fit drawn through the points with no confidence band around it.

(
    movie
    .ggplot(aes(c.rating_count, c.gross))
    .geom_point()
    .geom_smooth(method="lm", se=False)
    .scale_x_log10()
    .scale_y_log10()
)

5. Create a scatterplot of rating against gross, split into a grid of small panels, one for each MPA rating, with the points colored by MPA rating and the legend hidden. Then add a full set of labels to it.

(
    movie
    .ggplot(aes(c.rating, c.gross))
    .geom_point(aes(color=c.mpa), show_legend=False)
    .facet_wrap("mpa")
    .labs(
        x="Average viewer rating",
        y="Gross (millions of dollars)",
        title="Ratings and box office by MPA rating",
        caption="Data from IMDb"
    )
)

6. Join the people table to the movies data and count the number of films directed by each person. Hint: you need to join on both year and title.

# This is the better approach, because year and title together are the
# primary key of movie and a foreign key in people, so we put people on
# the left and movie on the right.
(
    people
    .filter(c.role == "director")
    .join(movie, on=[c.year, c.title])
    .group_by(c.person)
    .agg(count = pl.len())
)

7. A colleague sends you a new version of the movie table and you are not sure it has only one row per film. Write the code that would tell you, before you join anything, whether title on its own is a genuine primary key of that table. What happens to the join in question 6 if it is not, and why does Python not warn you?

(
    movie
    .select(c.title)
    .n_unique() == len(movie)
)

# If it comes back False, a title with two rows will match every row of
# people twice, so the join silently produces extra, duplicated rows.
# Nothing raises an error: Polars did exactly what we asked, which is to
# match every row of the left table against every matching row of the
# right table, however many there are. The row count is the only place
# the problem shows up, which is why we check the key beforehand.

8. Return the rows of people whose film does not appear anywhere in the movie table at all. Then keep only the films that have at least one person listed for them, without adding any new columns.

(
    people
    .join(movie, on=[c.year, c.title], how="anti")
)

(
    movie
    .join(people, on=[c.year, c.title], how="semi")
)

9. Add the gross of each film to the people table, keeping every person in the result even when the film is missing from the movie table.

(
    people
    .join(movie.select(c.year, c.title, c.gross), on=[c.year, c.title], how="left")
)

10. Compute the number of films with each MPA rating in each year, and then reshape the result so that there is one row for each year and one column for each MPA rating.

(
    movie
    .group_by(c.year, c.mpa)
    .agg(count = pl.len())
    .pivot(index=c.year, on=c.mpa, values=c.count)
    .fill_null(0)
)

11. Starting from the wide table in question 10, suppose you want to draw a line plot of the number of films over time, with one line per MPA rating. Explain why you cannot do this directly, and then write the code that reshapes the data and draws the plot.

# There is no mpa column in the wide table to map to the color
# aesthetic. Each MPA rating is a column name rather than a value of a
# variable, and plotnine has no way of knowing that those column names
# all belong to the same underlying variable. Unpivoting puts the MPA
# rating back into the data as a column.
(
    movie_wide
    .unpivot(index=c.year, variable_name=c.mpa, value_name=c.count)
    .ggplot(aes(c.year, c.count, color=c.mpa))
    .geom_line()
)

12. Pretend there exists a column in movie called genres, holding all of the genres of a film packed into a single cell as text and separated by the character |, as in "Drama|Romance". Write the code that turns the data into a table with one row for each film and each of its genres, and then report how many films fall into each genre.

(
    movie
    .with_columns(
        genre = c.genres.str.split("|")
    )
    .explode(c.genre)
    .group_by(c.genre)
    .agg(count = pl.len())
)
