Exam III Study Guide

[← back]

The third exam is 75 minutes. It has fifteen short questions spread across five tasks, labeled A through E. This exam works differently from the first two: you will not write any code. Instead, every task gives you a small table, often together with the code that runs on it, and your job is to say what comes out or to pick the statement that explains it. Every question is either multiple choice or fill-in-the-blank, and you write your answers directly on the exam:

  • Multiple choice (eight questions). Four options; circle the one best answer. The right answer is always clearly right, but at least one of the others will look plausible if you are not careful: it is usually the answer you get by making one of the mistakes we have discussed in class, such as forgetting that the default join drops unmatched rows, counting a repeated key twice in a semi-join, or using geom_bar where geom_col is needed.
  • Fill in the blank (seven questions). A number, a row count, or a short piece of text, with one correct answer. Most questions have two or three blanks. Numbers should be exact.

You do not need to memorize any function names or arguments. There is no reference sheet for this exam. Instead, anything you need is given with the question itself: what each kind of join keeps, the three rules of tidy data, what the arguments of .pivot() do, and how binwidth and boundary cut up a histogram are all stated where they are used. What you do need is to understand the ideas well enough to apply them to a small table in front of you. No calculator is needed.

The exam covers Chapter 7, Chapter 8, Chapter 9, and Chapter 10, along with Homeworks 12 through 14, 18, and 19.

What You Need To Know

The exam has five tasks. Each one uses a specific kind of table and tests a specific, short list of ideas. The lists below are complete: if an idea is not here, it is not on the exam.

Task A. Keys and joins (four questions). Two small tables: one with a row for each event (such as a flight) and one with a row for each thing the events refer to (such as an aircraft).

  1. A primary key identifies a row of its table. A foreign key is a primary key of another table that appears in this one, where it may repeat. The same column can be the primary key of one table and a foreign key in another; which it is depends on the table it sits in. A column is a primary key only if its number of distinct values (.n_unique()) equals the number of rows (len()).
  2. The default join keeps only the rows of the left table that have a match. how="left" keeps every row of the left table and fills null where there is no match. Give the number of rows each returns and the value a given row gets. When a key repeats in the left table, each of its rows gets the matching values.
  3. how="semi" keeps the rows of the left table that have a match, and how="anti" keeps those that do not. Neither adds any columns, and a semi-join never repeats a row, however many matches it has. Count the rows each returns.
  4. A row returned by an anti-join is a key with no match on the other side, which is worth chasing down: the other table may be incomplete, or the key may be mistyped.

Right, full, and cross joins, .join_asof, and .join_where are not on the exam.

Task B. Tidy data (three questions). A small table laid out the way someone might type it into a spreadsheet.

  1. The unit of observation is what each row of a table describes, such as carrier or carrier × day. Name the unit of observation of a table, and give the number of rows and columns in the tidy version for a different unit of observation.
  2. A table is tidy when every variable is a single column, every observation is a single row, and every table holds a single unit of observation. Every value in a table should describe the whole unit of observation: a fact about a carrier does not belong in a carrier × day table, and goes in its own table instead.
  3. A missing value is a blank cell: not a 0, not a special code, and not a note. Notes belong in a notes column or the data dictionary.

The spreadsheet guidelines (A1, sheets as tables, formatting), data dictionaries, the naming rules, dates, multimedia, and synthetic keys are not on the exam. They are covered by the homeworks and by your final project.

Task C. Pivot and explode (three questions). A long table of counts, and a table with several values packed into one cell.

  1. .pivot(index=, on=, values=) makes one row for each value of index, one new column for each distinct value of on, and fills the cells from values. Give the number of rows and columns of the result, and count the null cells left by combinations that never occurred. A pivot only rearranges values, so it can be undone; an aggregation such as a sum per group cannot.
  2. plotnine maps aesthetics to columns, so it needs the long table. In a wide table the categories are column names rather than values, so there is no column to map to color. .unpivot() puts them back into a column.
  3. .str.split("|") turns a packed cell into a list, and .explode() gives each element of the list its own row, copying the other columns. Count the rows after exploding and the rows after a following .group_by(), and read off one count.

The arguments of .unpivot() and .fill_null() are not on the exam.

Task D. Statistical geometries (three questions). A list of numbers, or a description of a table that has already been summarized.

  1. geom_bar counts the rows in each category for you; geom_col draws a number that is already a column of the table. Say which one a task calls for and why.
  2. A histogram cuts the number line into bins of width binwidth, with one edge at boundary, and the height of each bar is the number of values in its bin. Given a short list of numbers, give the height of a named bar and the number of bars.
  3. A boxplot box runs from the 25th to the 75th percentile of each group, with a line at the median. With five values in order, these are the second, fourth, and third values.

Density plots, geom_smooth, ordering categories with .over(), and casting a number to a string are not on the exam.

Task E. Facets and labels (two questions). A short block of plotting code.

  1. facet_wrap draws one small panel per category. By default all panels share the same axes, which is what makes them comparable; scales="free_y" gives each panel its own y-axis, which makes each panel easier to read and the panels harder to compare.
  2. .labs() changes only the labels it is given. Any label left out keeps its default, which is the name of the column.

Scale functions (scale_color_manual, scale_x_log10, the limits and breaks options), themes, and the best-practice guidelines are not on the exam.

Practice Questions

Every question below is in the exam's own format and uses a parallel dataset. Every question on the exam has a twin here, and there are a few extra practice questions beyond that, so this set is a little longer than the exam itself. Work through all of them with the tables in front of you, as you will on the day; the answers follow each question. If you can do these, you can do the exam. The questions use a small set of tables about films shown at three Richmond theaters.

Task A. Keys and Joins

The screening table has one row for each of six screenings, and the film table has one row for each of four films.

screeningtheatertitle
1ByrdVertigo
2ByrdJaws
3MovielandJaws
4MovielandHeat
5CriterionAlien
6ByrdPsycho
titleruntime
Vertigo128
Jaws124
Heat170
Rocky120

By default, .join() keeps only the rows of the left table that have a match in the right table. With how="left" it keeps every row of the left table and fills null where there is no match. With how="semi" it keeps the rows of the left table that have a match, and with how="anti" the rows that do not; neither adds any columns.

1. (Multiple choice.) Which statement about the column title is correct?

  1. It is a primary key of both tables, because it has the same name in each.
  2. It is not a key in either table, because Jaws appears twice in screening.
  3. It is a primary key of film and a foreign key in screening.
  4. It is a primary key of screening, because every screening shows exactly one film.
(C). Each film has one row in `film`, so `title` identifies a row there. In
`screening` one film can be shown many times (Jaws is shown twice), so there
it is a foreign key pointing back at `film`. Whether a column is a primary
or a foreign key depends on the table it sits in, not on its name, which
rules out (A). The repeat in `screening` is exactly what a foreign key is
allowed to do, which rules out (B).

2. (Fill in the blank.) The code screening.join(film, on=c.title) returns ________ rows. With how="left" added, it returns ________ rows, and the value of runtime for screening 6 is ________.

4;  6;  null.

Screenings 1 to 4 have a match, and Jaws matches both of its screenings, so
the default join keeps four rows. The left join keeps all six:

    screening  theater    title    runtime
    1          Byrd       Vertigo      128
    2          Byrd       Jaws         124
    3          Movieland  Jaws         124
    4          Movieland  Heat         170
    5          Criterion  Alien       null
    6          Byrd       Psycho      null

Alien and Psycho are not in `film`, so their runtime is null, not 0.

3. (Fill in the blank.) The code screening.join(film, on=c.title, how="anti") returns ________ rows. The code film.join(screening, on=c.title, how="semi") returns ________ rows.

2;  3.

The anti-join keeps screenings 5 and 6, whose films have no row in `film`.
The semi-join keeps the films that were shown at least once: Vertigo, Jaws,
and Heat. Jaws was shown twice but appears once, because a semi-join only
filters the rows of the left table and never repeats them. Rocky was never
shown and is dropped. Answering 4, by counting Jaws twice, is the tempting
wrong answer.

4. (Multiple choice.) Screening 5 appears in the output of the anti-join in question 3. What does that tell you?

  1. Screening 5 was cancelled, so it has no film.
  2. The film Alien has no row in film: either the table is incomplete or the title is mistyped, and it is worth finding out which.
  3. Alien is longer than any film in the film table.
  4. Screening 5 will be dropped from every join with film, whatever how is set to.
(B). An anti-join returns the rows whose key has no match on the other side,
which makes it a quick check on the quality of your data. Nothing in the
tables says anything about cancellations or runtimes. (D) is false: the left
join in question 2 kept screening 5.

5. (Fill in the blank.) The code screening.select(c.title).n_unique() returns ________, and len(screening) returns ________, so title ________ (is / is not) a primary key of screening.

5;  6;  is not.

There are five distinct titles in six rows, because Jaws repeats. A column is
a primary key only if the number of distinct values equals the number of
rows. `screening` is the column that identifies a row of this table.

Task B. Tidy Data

A theater manager records the number of tickets sold at four theaters on each day of one weekend in a spreadsheet, as below. A dataset is tidy when every variable is a single column, every observation is a single row, and every table holds a single unit of observation.

theaterfrisatsun
Byrd120210180
Movieland300420390
Criterion150260240
Westhampton80130110

6. (Fill in the blank.) The unit of observation of this table is ________. A tidy table with the unit of observation theater × day, holding the same numbers, has ________ rows and ________ columns.

theater;  12;  3.

Each row describes one theater. In the long table each row is one theater on
one day, 4 x 3 = 12 rows, with the columns theater, day, and tickets:

    theater    day   tickets
    Byrd       fri       120
    Byrd       sat       210
    Byrd       sun       180
    Movieland  fri       300
    ...

The day has moved out of the column names and into a column of its own. The
wide table is not wrong: it is tidy for the unit of observation theater.

7. (Multiple choice.) The manager adds a column capacity, the number of seats in each theater, to the 12-row theater × day table. What is wrong with this?

  1. Capacity is a fact about a theater, not about a theater on a day: it is repeated three times per theater, nothing stops the copies from disagreeing, and it belongs in a separate table with one row per theater.
  2. Nothing: every row now has all the information about its theater in one place.
  3. A capacity is a count, and a tidy table may not hold two counts.
  4. The column name is too short to describe what it holds.
(A). Every value in a table should describe the whole unit of observation.
Capacity describes a theater, so it goes once in a `theater` table, and we
join it in when an analysis needs it. (B) is the tempting answer: having
everything in one place is convenient, but it is what a join is for.

8. (Multiple choice.) Movieland's ticket count for Saturday was lost. Following the reading, what should that cell hold?

  1. 0, since no tickets were recorded.
  2. The value −1, a code that cannot be a real count.
  3. The text lost (register crashed), so that readers know why it is empty.
  4. Nothing: the cell should be left blank.
(D). A blank is the only way to mark a missing value that every program reads
the same way. A 0 claims that Movieland sold no tickets, which is a different
and false fact. A code like -1 will be averaged in by anyone who does not know
about it. The explanation belongs in a notes column or in the data dictionary,
never in the cell itself, where it would turn a numeric column into text.

Task C. Pivot and Explode

The counts table gives the number of screenings at each theater in each of three weeks. Not every theater showed a film every week.

weektheatern
1Byrd50
1Criterion40
2Byrd45
2Movieland30
3Criterion35
3Movieland20
counts_wide = (
    counts
    .pivot(index=c.week, on=c.theater, values=c.n)
)

The index column gives the rows of the output, each distinct value of the on column becomes a new column, and the values column fills the cells.

9. (Fill in the blank.) counts_wide has ________ rows and ________ columns, and ________ of its cells are null.

3;  4;  3.

    week   Byrd   Criterion   Movieland
    1        50          40        null
    2        45        null          30
    3      null          35          20

One row per week, and four columns: `week` plus one per theater. The nine
theater cells hold the six counts in the long table; the other three
combinations never occurred, so they are null. Forgetting the `week` column
(3 columns) is the tempting wrong answer.

10. (Multiple choice.) Why can't plotnine draw a line plot with one line for each theater directly from counts_wide?

  1. The table would first have to be sorted by theater.
  2. plotnine cannot draw a plot from a table that contains null values.
  3. Line plots need at least five points per line, and each theater has only three weeks.
  4. There is no theater column to map to the color aesthetic: the theaters are column names, not values. Unpivoting puts them back into a column.
(D). plotnine maps aesthetics to columns. In the wide table, Byrd, Criterion,
and Movieland are three separate columns, and nothing tells plotnine that
they are three values of one variable. The long `counts` table already has a
`theater` column, which is why plotnine prefers long data.

11. (Multiple choice.) What is the difference between pivoting counts to counts_wide and computing counts.group_by(c.theater).agg(total = c.n.sum())?

  1. There is none: both produce one row per theater.
  2. The pivot only rearranges the numbers, so unpivoting gets them all back; the aggregation adds them up, and the weekly counts cannot be recovered from the totals.
  3. The pivot loses the week, and the aggregation keeps it.
  4. The aggregation is tidy and the pivot never is.
(B). Pivoting and unpivoting are round trips: no values are created or
destroyed, only moved. Aggregation changes the unit of observation in one
direction only. This is the reason the reading recommends storing data long:
a long table can always be pivoted into whatever wide shape you need, but an
aggregated table cannot be un-aggregated.

The film table has a column listing each film's genres, packed into one cell and separated by |.

12. (Fill in the blank.) Before the .group_by(), the exploded table has ________ rows. The final result has ________ rows, and the value of n for Drama is ________.

7;  3;  3.

Exploding gives one row per film and genre: 2 + 1 + 3 + 1 = 7 rows, with the
title copied onto each one. There are three distinct genres (Drama, Thriller,
and Crime). Drama appears for Vertigo, Heat, and Rocky; Thriller also has 3,
and Crime has 1.

Task D. Statistical Geometries

13. (Multiple choice.) A classmate computes the average attendance at each theater with .group_by(c.theater) and .agg(avg = c.attendance.mean()), and wants to draw each average as a bar. Which geometry should they use, and why?

  1. geom_col, because the height of each bar is already a column of the table; geom_bar would count the rows instead.
  2. geom_bar, because it computes the average of each group for you.
  3. geom_histogram, because the averages are numeric.
  4. geom_bar, because the plot is a bar plot.
(A). `geom_bar` takes a single categorical aesthetic and counts the rows in
each category for you. Handed the summary table, which has one row per
theater, it would draw every bar with a height of 1. `geom_col` takes an x
and a y and draws each y as given. Neither one computes an average, which
rules out (B).

14. (Fill in the blank.) The code screening.ggplot(aes(c.theater)).geom_bar(), using the screening table from Task A, draws ________ bars, and the bar for Byrd has a height of ________.

3;  3.

One bar per theater (Byrd, Movieland, Criterion), and Byrd has three rows in
`screening` (screenings 1, 2, and 6). Here geom_bar is the right choice,
because the count is what we want and the table has no count column.

The runtimes, in minutes, of ten films are:

85    92    98    104    107    112    118    126    133    151

They are drawn with geom_histogram(binwidth=20, boundary=0), which cuts the number line into bins 20 minutes wide, with one bin edge at 0, and draws one bar for each bin from the lowest value to the highest.

15. (Fill in the blank.) The bar spanning 100 to 120 minutes has a height of ________, and the histogram has ________ bars.

4;  4.

With an edge at 0 and a width of 20, the edges fall at 80, 100, 120, 140, and
160, and the bins hold:

    80 to 100:   85, 92, 98             3
    100 to 120:  104, 107, 112, 118     4
    120 to 140:  126, 133               2
    140 to 160:  151                    1

The height of a bar is the number of films whose runtime falls in that bin.

16. (Fill in the blank.) The attendance at the Byrd's five screenings last week was 20, 40, 50, 70, and 90. In a boxplot of attendance by theater, the box for Byrd runs from the 25th to the 75th percentile, which here is from ________ to ________, with a line at the median, ________.

40 to 70, with a line at 50.

With five values in order, the median is the third, and the 25th and 75th
percentiles are the second and the fourth. These are the three numbers that
geom_boxplot computes for each group before it draws anything. Giving the
smallest and largest values (20 and 90) is the tempting wrong answer: those
are where the whiskers reach, not the box.

Task E. Facets and Labels

The screening_full table has one row for each screening, with columns including theater, runtime, and attendance.

(
    screening_full
    .ggplot(aes(c.runtime, c.attendance))
    .geom_point(aes(color=c.theater), show_legend=False)
    .facet_wrap("theater")
)

17. (Multiple choice.) This code draws one small panel per theater. A classmate changes the last line to .facet_wrap("theater", scales="free_y"), which gives each panel its own range on the y-axis. Which statement is correct?

  1. The panels can now be compared more easily, because each theater's attendance fills its whole panel.
  2. Each panel becomes easier to read on its own, but a point that sits higher in one panel no longer necessarily has a larger attendance than a lower point in another panel.
  3. The x-axis of each panel also gets its own range.
  4. Nothing changes, because every panel already has its own axes.
(B). By default every panel shares one x-axis and one y-axis, which is what
makes the panels comparable at a glance, and it rules out (D). Freeing the
y-axis trades that comparison for legibility within each panel, the opposite
of (A). Only the y-axis is freed, so (C) is false.

18. (Multiple choice.) The original plot has .labs(y="Tickets sold", title="Attendance and runtime") added to it. Which statement describes the result?

  1. The x-axis has no label, because .labs() replaces every label at once.
  2. The code raises an error, because .labs() needs a label for every aesthetic in the plot.
  3. The x-axis is labeled runtime, because any label not given to .labs() keeps its default, the column name.
  4. The title replaces the label on the x-axis.
(C). `.labs()` changes only the labels it is given and leaves the rest alone.
The defaults are the column names, which is why they are fine while you are
exploring (they are the names you type) and worth replacing before you show
the plot to anyone else.
