Assume you have two datasets loaded into Python. The first, semesters, has one row for each student in each semester they have been enrolled, with columns named name, semester, and gpa. The second, students, has one row for each student, with columns named name, major, year, gpa, and languages, the last of which holds all of the languages a student speaks packed into a single cell as text, separated by the character |, as in "en|fr|es". Hand write the following.

  1. The code that reshapes semesters into a table with one row for each semester and one column for each student, holding their GPA. Then write the code that turns the result back into a table with one row for each student in each semester.
  2. A sentence naming the unit of observation of each of those two tables, and a question about the data that would be easier to answer with the wide one than with the long one.
  3. Suppose you have only the wide table and you want to draw a line plot of GPA over time with one line per student. Explain in a sentence or two why you cannot do this directly, and then write the code that reshapes the data and draws the plot.
  4. The code that turns students into a table with one row for each student and each language they speak, followed by the code that reports how many students in the class speak each language.
  5. A short explanation, in your own words, of why we can pivot a table and then unpivot it back without losing anything, but cannot undo an aggregation the same way, and of what this implies about the shape in which we should store a dataset that we plan to keep for a long time.

Solutions

1. Reshape semesters to one row per semester and one column per student, then turn it back.

gpa_wide = (
    semesters
    .pivot(index=c.semester, on=c.name, values=c.gpa)
)

(
    gpa_wide
    .unpivot(index=c.semester, variable_name=c.name, value_name=c.gpa)
)

Setting variable_name and value_name gives the columns their original names back instead of the defaults variable and value. A student who was not enrolled in some semester gets a null in the wide table. After the unpivot, that null becomes an extra row with a missing GPA. Adding .drop_nulls() removes those rows, but it also removes any semester whose GPA was already missing in semesters.

2. Name the unit of observation of each table, and give a question that is easier to answer with the wide one.

The wide table has the unit of observation semester. The long table
has the unit of observation student × semester.

The wide table makes it easier to compare specific students, such as
"In each semester, how much higher was Ana's GPA than Ben's?" With
one column per student, that is a single subtraction of the Ana
column minus the Ben column.

3. Explain why a line plot with one line per student cannot be drawn directly from the wide table, then reshape the data and draw it.

(
    gpa_wide
    .unpivot(index=c.semester, variable_name=c.name, value_name=c.gpa)
    .ggplot(aes(c.semester, c.gpa, color=c.name))
    .geom_line()
)

One line per student means mapping color to the student, but in the wide table the student is not a column. The students are spread across the column names, so there is nothing to write inside aes(). Unpivoting puts name back as a column, and color=c.name then gives each student a line.

4. Turn students into one row per student and language, then count how many students speak each language.

student_lang = (
    students
    .select(c.name, c.languages)
    .with_columns(
        language = c.languages.str.split("|")
    )
    .explode(c.language)
)

(
    student_lang
    .group_by(c.language)
    .agg(pl.len().alias("n"))
    .sort(c.n, descending=True)
)

.str.split("|") turns each cell into a list of language codes, and .explode() gives each item in the list its own row, copying the student's name onto each one. The .select is optional, but it keeps the other columns from being repeated. Each student lists each language once, so counting rows gives the number of students who speak it.

5. Explain why a pivot can be undone but an aggregation cannot, and what that means for how to store data long term.

A pivot only rearranges the values. Every GPA in the long table is
still in the wide table, just in a different place, so unpivoting
can put each one back where it came from. An aggregation replaces many
values with one summary, such as a mean or a maximum, and throws the
original values away. Many different sets of values give the same
mean, so there is no way to work backward from the summary to the
original rows.

This means a dataset we plan to keep should be stored in its most
detailed, long form, with one row for each smallest unit we recorded.
From there we can pivot to any wide shape or aggregate to any summary
an analysis needs. Once a table has been aggregated, the detail is
gone for good.
