As in the previous homework, assume you have a dataset loaded into Python called students, with columns named name, major, year, gpa, and study_hours. Some students have not yet been assigned a GPA, so that column contains missing values. Hand write the following.

  1. The code that returns a table with one row for each major, giving both the number of students in that major and the number of those students who actually have a GPA recorded, followed by a sentence explaining why it is worth knowing the difference before trusting an average GPA.
  2. The code that returns the number of distinct majors represented in the class.
  3. The code that summarizes the entire dataset in a single row, giving the total number of study hours, the average GPA, and the number of students, along with a sentence explaining why we cannot use .agg to do this.
  4. The code that returns a table with one row for each major, giving the smallest GPA, the largest GPA, the median GPA, and the correlation between study hours and GPA within that major.
  5. Finally, in a sentence or two of your own words, explain what it means to say that aggregation reduces rows, and give an example of a question about these students that aggregation therefore cannot answer.

Solutions

1. For each major, count the students and count the students who have a GPA recorded, then explain why the difference matters.

(
    students
    .group_by(c.major, maintain_order=True)
    .agg(
        n = pl.len(),
        n_gpa = c.gpa.count()
    )
)

pl.len() counts every row in the group. c.gpa.count() counts only the non-missing values in the gpa column, so it is smaller in any major where some students have no GPA yet. The difference matters because an average GPA is computed only from the students who have one. If a major has twelve students but only two GPAs, its average is built from those two, and nothing in a column of averages shows that.

2. Count the distinct majors in the class.

(
    students
    .select(n_majors = c.major.n_unique())
)

There is no grouping here because the question asks for one number about the whole class. .n_unique() counts different values, not rows. It treats a missing value as one more distinct value, so if some students had no major listed, the count would be one higher than the number of real majors.

3. Summarize the whole dataset in one row with the total study hours, the average GPA, and the number of students, and explain why .agg will not work.

(
    students
    .select(
        study_hours_total = c.study_hours.sum(),
        gpa_avg = c.gpa.mean(),
        n = pl.len()
    )
)

In Polars, .agg always follows a .group_by, and here there are no groups, so calling it directly on students is an error. .select accepts the same aggregating expressions and collapses the whole frame to a single row. The average GPA uses only the students who have one, while pl.len() counts all of them, including those still waiting for a GPA.

4. For each major, give the smallest, largest, and median GPA, along with the correlation between study hours and GPA.

(
    students
    .group_by(c.major, maintain_order=True)
    .agg(
        gpa_min = c.gpa.min(),
        gpa_max = c.gpa.max(),
        gpa_median = c.gpa.median(),
        gpa_corr = pl.corr(c.study_hours, c.gpa)
    )
)

The column names are your choice. The first three summaries are methods called on the gpa column. The correlation is different: it needs two columns, so it is written as the function pl.corr with both columns passed in. maintain_order=True is optional, since the question does not ask for any particular order.

5. Explain what it means for aggregation to reduce rows, and give a question about the students that aggregation cannot answer.

Aggregation takes all the rows in a group and returns one row that
summarizes them. After computing the average GPA for each major, the
individual students are gone from the result; their GPAs went into the
average and the rows were thrown away. So aggregation cannot answer
"how far above or below their major's average GPA is each student?",
because that answer needs the major's average and one row per student
at the same time.

This is one possible answer; there is no single correct one. Check that yours says the result has exactly one row per group and that the original rows are gone. Your example should be a question whose answer needs a group-level number attached to every individual student. The next chapter introduces the tool for that kind of question.
