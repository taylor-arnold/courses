Assume you have a dataset loaded into Python called students, with columns named name, major, year, gpa, and study_hours. Hand write the following, writing each one as its own chain of methods that follows the formatting conventions from the reading.

  1. The code that returns the single student with the highest GPA in each major.
  2. The code that returns a table with one row for each major, giving the average GPA of the students in that major and the number of students in that major, with the rows coming back in a predictable order.
  3. The code that returns a table with one row for each combination of major and year, giving the average number of study hours for the students in that group.
  4. The code that returns a table with one row for each major, giving the number of students in that major with a GPA above 3.5, without adding any new columns to the dataset first.
  5. Finally, in a sentence or two of your own words, describe what Polars gives you back if you call .group_by and then stop, and explain why there is nothing in Polars that corresponds to "ungrouping" a dataset.

Solutions

1. Return the student with the highest GPA in each major.

(
    students
    .sort(c.gpa, descending=True)
    .group_by(c.major)
    .head(n=1)
)

This is the sort-then-group pattern from the reading. The .sort has to come before .group_by, so that the rows reach each group already ordered from highest GPA to lowest and .head(n=1) keeps the top one. Without the sort, the first row of each group is whatever student happens to come first in the data. If two students in a major tie for the highest GPA, this code still returns only one of them.

2. Give the average GPA and the number of students for each major, with the rows in a predictable order.

(
    students
    .group_by(c.major, maintain_order=True)
    .agg(
        gpa_avg = c.gpa.mean(),
        n = pl.len()
    )
)

The names gpa_avg and n are your choice. The part of the question about order points to maintain_order=True. Without it, Polars builds the groups in parallel and the rows can come back in a different order each time you run the code. With it, the majors appear in the order their first row appears in students. Adding .sort(c.major) after the .agg also gives a fixed order, so either answer is fine.

3. Give the average number of study hours for each combination of major and year.

(
    students
    .group_by(c.major, c.year, maintain_order=True)
    .agg(
        study_hours_avg = c.study_hours.mean()
    )
)

Both columns go inside the same .group_by, separated by a comma. Each row of the result is one combination of major and year that occurs in the data. A combination with no students, such as a major that has no first-year students, does not get a row. The question does not ask for an order, so maintain_order=True is optional here.

4. Count the students with a GPA above 3.5 in each major, without adding a new column first.

(
    students
    .group_by(c.major, maintain_order=True)
    .agg(
        n_high_gpa = (c.gpa > 3.5).sum()
    )
)

The comparison c.gpa > 3.5 gives a column of true and false values, and .sum() counts the true ones. Because the expression is built inside .agg, there is no need to create the column with .with_columns beforehand, which is what the question rules out. Do not use .filter(c.gpa > 3.5) before grouping here. It gives the right counts for most majors, but a major with no students above 3.5 disappears from the result instead of showing a count of zero.

5. Describe what .group_by returns on its own, and explain why Polars has no way to ungroup.

Calling .group_by and stopping gives back a GroupBy object, not a
DataFrame. It has no rows or columns to print, only an instruction that
the next method should run once per group. Polars has nothing like
ungroup because the grouping only lasts until the next method (such as
.agg or .head) uses it up. What that method returns is an ordinary
DataFrame with no grouping attached, so there is nothing to remove.

Your wording will differ. Check that your answer says two things: that the result is a GroupBy object rather than a table, and that the grouping is consumed by the very next method instead of staying attached to the data, as it does in R's dplyr.
