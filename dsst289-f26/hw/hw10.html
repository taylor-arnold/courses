Assume you have two datasets loaded into Python. The first, students, has one row for each student in the class, with columns named name, major, year, gpa, and study_hours. The second, semesters, has one row for each student in each semester they have been enrolled, with columns named name, semester (a number counting up from one), and gpa. Hand write the following, writing each one as its own chain of methods that follows the formatting conventions from the reading.

  1. The code that adds a column to students giving each student's study hours as a percentage of all of the study hours put in by the students in their major, keeping every student in the result.
  2. The code that adds a column to students holding the average GPA of the student's major, followed by a sentence describing how the shape of this result differs from the table you would get by computing the same averages with .group_by and .agg.
  3. The code that keeps only the students whose GPA is above the median GPA of their own major, without adding any new columns to the dataset.
  4. The code that adds a column to semesters giving the change in each student's GPA from the previous semester, along with a sentence explaining what would go wrong if you left the .over() off, and a sentence explaining which rows of the result come back as missing values and why.
  5. A few students have a semester with no GPA recorded. Write the code that replaces each of those missing values with that student's most recent previously recorded GPA.

Solutions

1. Add each student's study hours as a percentage of the total study hours in their major, keeping every student.

(
    students
    .with_columns(
        study_share = c.study_hours / c.study_hours.sum().over(c.major) * 100
    )
)

Read the expression from the inside out. c.study_hours.sum() is a total, and .over(c.major) computes that total separately within each major and writes it onto every student in the major. The division then happens row by row. Put the aggregation first and .over() second. Writing c.study_hours.over(c.major).sum() runs without an error, but every student gets the total for the whole class.

2. Add a column with the average GPA of each student's major, and describe how the shape differs from the .group_by and .agg version.

(
    students
    .with_columns(
        gpa_major_avg = c.gpa.mean().over(c.major)
    )
)

This result has one row for each student and keeps all of the original columns, with the major's average repeated on every student in that major. The .group_by and .agg version holds the same averages, but it has one row for each major and only two columns: major and the average.

3. Keep only the students whose GPA is above the median GPA of their own major, without adding a column.

(
    students
    .filter(c.gpa > c.gpa.median().over(c.major))
)

A windowed expression is still an expression, so it can go directly inside .filter. The median of each major is computed, compared against each student, and then discarded, so no new column appears in the result. Students with no GPA are also dropped, because comparing a missing value gives a missing result and the filter keeps only rows where the condition is true.

4. Add a column to semesters with the change in each student's GPA from the previous semester. Explain what goes wrong without .over() and which rows come back missing.

(
    semesters
    .sort(c.name, c.semester)
    .with_columns(
        gpa_change = c.gpa - c.gpa.shift(1).over(c.name)
    )
)

The sort comes first because "the previous semester" only means something once each student's rows are in semester order. .shift(1) looks one row up, and .over(c.name) keeps it from looking across the boundary between two students.

Without the .over(), each student's first semester would be compared with the last semester of whichever student sorts just before them. The code would still run, and those rows would show a change in GPA that is meaningless.

Each student's first semester comes back missing, because there is no earlier semester to subtract. Since some GPAs are missing in this data (see question 5), a semester with no GPA also gives a missing change, as does the semester right after it. A missing value in a subtraction makes the result missing.

5. Replace each missing GPA in semesters with that student's most recent earlier GPA.

(
    semesters
    .sort(c.name, c.semester)
    .with_columns(
        gpa = c.gpa.forward_fill().over(c.name)
    )
)

.forward_fill() replaces each missing value with the closest value above it, so the rows have to be sorted by student and semester first. The .over(c.name) matters here for the same reason as in question 4. Without it, a student whose first semester is missing would take a GPA from a different student. With it, that first semester stays missing, since the student has no earlier GPA to borrow. Giving the new column the name gpa replaces the old column; a new name such as gpa_filled is also fine if you want to keep both.
