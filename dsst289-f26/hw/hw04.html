As in the previous homework, assume you have a dataset loaded into Python called students, with columns named name, major, year, and gpa. Hand write the following, writing each one as its own chain of methods that follows the formatting conventions from the reading.

  1. The code that changes the name of the column gpa to grade_point_average.
  2. The code that returns exactly one row for each major in the dataset.
  3. The code that adds a new column named gpa_100 holding each student's GPA on a 100-point scale (that is, the GPA divided by 4 and multiplied by 100), keeping all of the other columns as they are.
  4. The code that adds a new column named honors that is equal to 1 for students with a GPA of at least 3.5 and 0 for everyone else.
  5. Finally, in a sentence or two of your own words, explain what the .pipe method does and why we would want it when we already have a chain of methods.

Solutions

1. Give the gpa column a longer name.

(
    students
    .rename({"gpa": "grade_point_average"})
)

The argument is a dictionary, with the old name on the left of the colon and the new one on the right. Both names are quoted strings here, not c. columns.

2. One row per major.

(
    students
    .unique(subset=["major"])
)

The subset goes in square brackets even when it names a single column. Without the subset, .unique would compare whole rows and hand back nearly everything, since two students rarely match on name, year, and GPA all at once.

3. Add a gpa_100 column with the GPA rescaled to run from 0 to 100.

(
    students
    .with_columns(gpa_100 = c.gpa / 4 * 100)
)

Use .with_columns rather than .select: the question asks to keep the other columns, and that is the only difference between the two methods. The new name sits on the left of a single equals sign and is written plainly, with no quotes and no c. prefix.

4. Add an honors column equal to 1 for a GPA of 3.5 or higher and 0 otherwise.

(
    students
    .with_columns(
        honors = pl.when(c.gpa >= 3.5).then(1).otherwise(0)
    )
)

A column built from a condition calls for pl.when, and every .when().then() needs an .otherwise() to say what happens to the rows that did not match. "At least 3.5" is >=, so a student sitting exactly at 3.5 counts as honors. The definition is long enough to earn its own indented line inside .with_columns.

5. In your own words, what .pipe does and why it is worth having.

There is no single correct wording here. A good answer says both of these things:

  - .pipe hands the DataFrame to a function as that function's first
    argument, so df.pipe(f) does the same thing as f(df).

  - It is useful because a chain only reaches methods that Polars itself
    defines. .pipe lets you drop any function you like into the middle of
    a chain, as one more step, instead of wrapping it around the outside
    and breaking the top-to-bottom reading order.

One possible answer: "The .pipe method passes the data to a function of my
choosing, so f(df) can be written as df.pipe(f). That matters because
chaining otherwise limits me to Polars' own methods, and .pipe lets an
outside function join the chain without interrupting it."

Check that you said what .pipe actually does, not only that it is
convenient, and that your reason mentions functions outside of Polars.
