Your schema was locked at the workshop and collection begins the day this is due, so the first two parts below document a dataset that is now actually being filled in. The last three parts use today's reading to think about the shape of the data you are about to collect. As with Homeworks 15 and 16, type this rather than hand writing it, so that it can be submitted through Box.

  1. A complete data dictionary for every table in your project. For each variable, give its name, its type, its units or its expected set of values, and any decision you had to make in recording it. Document the relationship between every pair of tables that are linked, and note anywhere the key has a different name in the two tables.
  2. The three error-prone details from the end of Chapter 8, applied to your own tables. Point to the column that records a date and write out the exact format you are using. Add a column somewhere in your schema holding the file name of an image, a recording, or another file associated with a row. Then add a synthetic key to one table, and explain in a sentence why the natural key either was or was not sufficient on its own.
  3. Your hours table is stored in a long layout, with one row for each hour of the fourteen days. Pick one of your numeric measures and write the code that would pivot the table into a wide layout with one row for each date and one column for each hour of the day, holding that measure. Name the unit of observation of the result, give the number of rows and columns it will have when collection is finished, and give one question about your data that would be easier to answer from the wide table than from the long one.
  4. The code that turns your wide table from part (3) back into the long layout, naming the two new columns so that they match the column names of your original hours table. Then give two reasons, drawn from the reading, why the long layout is the right one to collect in and to store.
  5. Chapter 8 told you to keep every cell atomic. Suppose that you had given in and recorded, say, every person you were with during an hour in a single cell, separated by |. Write the code that would turn that column into one row for each hour and each person. Then name the unit of observation of the result, explain why it is no longer a valid hours table, and say where in your actual schema that information lives, or would live if you recorded it.
