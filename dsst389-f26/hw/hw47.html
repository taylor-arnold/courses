This reading treats images as arrays of numbers and computes brightness and color from the pixels directly. The first two questions ask you to do that arithmetic by hand.

  1. OpenCV reads the following 2×2 image, printed exactly as it would appear in Python:

    [[[255, 0, 0], [0, 0, 255]],
     [[0, 255, 0], [255, 255, 255]]]

    Give the shape of the array and name the color of each of the four pixels. Then compute the mean pixel value of the whole image, which is the brightness the reading would record for it. Say how many numbers you averaged over, and note the trap that catches most people reading this array for the first time.
  2. Take a pixel whose RGB values, scaled to the range 0 to 1, are R = 0.2, G = 0.6, B = 0.4. Compute M, m, and the chroma C, then compute the hue, saturation, and value using the formulas in the reading. Now do the same for a pixel with R = G = B = 0.5. Say what happens to the hue formula for the second pixel and why the answer is not meaningful. Then explain why compute_colors has to look at saturation and value, and not only hue, before it can call a pixel red or yellow.
  3. The darkest images in the collection turn out to be the ones with black backgrounds, and the brightest are the ones with white backgrounds. Say what the brightness column is therefore a measurement of. The reading then reports that peacock photographs are the darkest of the ten species. Say what that finding is a fact about, and what it is not a fact about.
  4. The images with the most yellow pixels include a lot of hummingbirds photographed against yellow-green foliage. Given that, say what would go wrong if you used the color proportion columns as features to predict a bird's species. Then name one thing these simple pixel features are genuinely good for, since the reading is not arguing that they are useless.
