Exam II Study Guide

[← back]

The second exam is 75 minutes. It has twenty-one short questions spread across five tasks, labeled A through E. As on the first exam, every task gives you a small dataset — a printed table, a handful of tokens — together with the code that runs on it, and your job is to say what comes out. What is different this time is how you answer. Every question is either multiple choice or fill-in-the-blank, and you write your answers directly on the exam:

  • Multiple choice (ten questions). Four options; circle the one best answer. The right answer is always clearly right, but at least one of the others will look plausible if you are not careful: it is usually the answer you get by making one of the mistakes we have discussed all unit, such as forgetting a null, letting a shift run across a group boundary, or reading a boundary as strict when it is inclusive.
  • Fill in the blank (eleven questions). A number, a date, a row count, or a short piece of text, with one correct answer. Many questions have two or three blanks. Numbers should be exact or rounded to two decimal places (a third decimal place is fine), with units where they apply. Write a datetime in the form 2025-02-18 03:00:00 (the seconds may be left off when they are zero) and a duration in days, hours, and minutes, such as 6 days 17 hours 50 minutes; a duration converted to a single unit, such as a count of minutes, is also accepted.

You do not need to memorize any function names, arguments, or formulas. There is no reference sheet for this exam. Instead, anything you need is given with the question itself: when a question uses a formula (TF-IDF, Euclidean distance) or depends on how a method behaves (what strategy="backward" means, what a format code such as %d stands for), the question states it. What you do need is to understand the ideas well enough to apply them to a table in front of you. Bring a calculator; a few questions ask for a natural logarithm or a square root.

The exam covers Chapter 13, Chapter 14, and Chapter 15, along with Homeworks 37 through 43. Chapter 12 (Data APIs) is deliberately not tested here: the API work is hard to assess on paper, and it is exercised directly in the final project, which relies on it heavily.

What You Need To Know

The exam has five tasks. Each one uses a specific kind of table and tests a specific, short list of ideas. The lists below are complete: if an idea is not here, it is not on the exam.

Task A. Dates and times (four questions). The table is an edit log: one row per edit, with a doc_id, a timestamp, a user, and a size.

  1. A timestamp arrives from an API as a string and is parsed with .str.to_datetime() and a format string. The format codes are given to you (%Y year, %m month, %d day, %H hour, %M minute, %S second); every other character in the format has to match the string exactly. You should be able to say what comes out when a string is parsed with a particular format, including the case where the format reads the day as the month: a date such as 06/01/2025 parses without complaint under either reading, which is the argument for the ISO layout.
  2. The .dt namespace pulls components out of a datetime: .dt.hour(), .dt.weekday() (Monday is 1, Sunday is 7), and .dt.date(), which keeps the date and drops the time. Given a row, read off each of these.
  3. .dt.truncate("1h") and .dt.truncate("1d") round a datetime down to the start of the hour or day, keeping the type as a datetime. .dt.round("1d") rounds to the nearest midnight, so anything after noon moves to the next day. Truncation is the right tool for counting events per day; know what changes if a classmate rounds instead.
  4. pl.datetime(2025, 1, 7) is an exact instant, midnight at the start of 7 January, and pl.date(2025, 1, 7) is a date. Comparing a datetime column against the instant with > keeps everything on the 7th after midnight, which is the whole day; comparing .dt.date() against the date with > drops the 7th entirely. Count how many rows each kind of filter keeps.
  5. Counting edits per day means truncating (or taking the date) and then .group_by() with pl.len(). Read the busiest day off a small table.

Time zones are not on the exam. You should know that they exist and that Wikipedia reports timestamps in UTC, but no question asks you to convert between zones.

Task B. Window functions on time (four questions). The same edit log, sorted by doc_id and then timestamp.

  1. c.size.diff() is c.size - c.size.shift(1). With .over(c.doc_id) it restarts for each page, so the first row of each page is null. Without it, the first row of the second page is compared against the last row of the first page, producing a number that describes an edit that never happened. Give both values.
  2. A comparison against null is null, not false, and ~null is still null. .filter() keeps only rows that are true, so nulls are dropped whichever way the filter is written. Count the rows that survive a filter such as .filter(~c.is_reversion), where is_reversion is c.size == c.size.shift(2).over(c.doc_id).
  3. Subtracting a shifted timestamp column from the timestamp gives a duration, the gap since the previous edit to the same page. Read individual gaps off the table, find the largest, and count the nulls (one per page). A negative shift such as c.size.shift(-1).over(c.doc_id) pulls the value from the row below, so its nulls fall at the bottom of each page rather than the top.
  4. Filtering on the shifted or differenced column, such as .filter(c.size_diff < 0) to find edits that shrank a page, and naming the rows that come back.

Rolling means, the rolling_mean_by family, and the total_hours() and total_days() conversions are not on the exam.

Task C. Joining on time (three questions). Two more tables appear: a page view table with doc_id, year, month, day, and views, and a metadata table with doc_id, born, and died.

  1. The page view table is turned into a datetime column at midnight of each day with pl.date(c.year, c.month, c.day).cast(pl.Datetime), and the edit log is joined to it with .join_asof(). With strategy="backward" each edit is matched to the most recent view record at or before it, which for a daily table is the record for the day of the edit. Like a left join, every edit row is kept. Fill in the views matched to a given edit.
  2. When the view table stops before the last edit, backward reaches back to the last record it has, however stale, rather than returning null. Know which row gets a stale value and what value it gets.
  3. by="doc_id" requires an exact match on the page before the nearest-in-time search runs, so an edit is never matched to another page's readership. It does the job that .over() does for shifts.
  4. .join_where() keeps every pair of rows that satisfies a condition, with the right table's columns suffixed _right. On a self join of the metadata table, count the rows that a lifetime-overlap condition returns. A symmetric condition returns each overlapping pair twice, once in each order; an asymmetric one such as c.born <= c.born_right returns it once. Spot the author who overlaps nobody.

The nearest strategy and the tolerance argument are not on the exam.

Task D. Annotations (six questions). The table is an annotation table for one short page, with the columns doc_id, sid, tid, token, lemma, upos, and is_alpha. It is always handed to you as data; you are never asked to predict what spaCy would do.

  1. sid numbers the sentences within a document and tid numbers the tokens within each sentence, restarting at 1 in every sentence. The three columns doc_id, sid, tid together form the primary key. Because tid restarts, c.tid.max() within a document is the length of the longest sentence, not the number of tokens; pl.len() counts tokens.
  2. Bigrams are built by filtering to alphabetic tokens, then c.lemma.shift(-1).over([c.doc_id, c.sid]), then dropping the rows whose next token is null. Count the bigrams a page produces (each sentence contributes one fewer than its number of surviving tokens). Know that numbers and punctuation are removed before the shift, so their neighbors get paired with each other, and that dropping c.sid from the .over() lets the shift run across the sentence boundary and manufactures one extra bigram per boundary.
  3. The content word ratio: filter to alphabetic tokens, flag the rows whose upos is in ["NOUN", "VERB", "ADJ", "ADV"], and divide the count of flagged rows by the count of words. Proper nouns are not in the list.
  4. Mean sentence length counts alphabetic tokens per sentence and averages. Mean word length is the mean number of characters in the token column (not the lemma) over alphabetic tokens.
  5. The type-token ratio is distinct lemmas over tokens. On a short page it is near 1 and says nothing, and across pages of different lengths it ranks pages mostly by shortness. Be able to pick the statement that says what a TTR ranking actually measures.

Pointwise mutual information, named entities (ent_type, ent_iob, the cumulative sum), and dependency parsing (dep, head_idx, subject-verb joins) are not on the exam.

Task E. TF-IDF and document vectors (four questions). A corpus of four short documents, each already lemmatized and filtered to alphabetic tokens, listed as rows of terms.

  1. The term-frequency matrix has one row per document and one column per distinct term in the corpus. Give its dimensions and the value of a specific cell (a term's count in a document), and know that most cells are zero.
  2. TF-IDF with the smoothed formula, which is given on the exam: tf_norm is a term's count divided by the number of tokens in its document, df is the number of documents containing the term, N is the number of documents, and tfidf = tf_norm × (ln((N + 1) / (df + 1)) + 1). Compute a score for a given term and document. A term in every document still gets a non-zero score because of the trailing +1.
  3. min_df and max_df are proportions of documents, and the boundaries are inclusive: a term in exactly half the documents survives max_df=0.5. List the terms that survive a given pair.
  4. The Euclidean distance between two vectors is the square root of the sum of squared differences. Compute it for small integer vectors, name the nearest neighbor, and recognize when a far-away document is only far because it is longer (one vector a multiple of another).

The angle (cosine) distance, UMAP, and the internals of compute_tfidf are not on the exam.

Practice Questions

Every question below is in the exam's own format and uses a parallel dataset. Every question on the exam has a twin here, and there are a few extra practice questions beyond that, so this set is a little longer than the exam itself. Work through all of them with the tables in front of you and a calculator, as you will on the day; the answers follow each question. If you can do these, you can do the exam. The questions use a small corpus of three authors, identified by doc_id: Ada Kerr, Bram Vale, and Cleo Nash.

Task A. Dates and Times

The revisions table holds the recent edits to two of the pages. The Wikipedia API returns each timestamp as a string such as "2025-02-10T14:20:00Z", and the column has been parsed into a datetime with c.timestamp.str.to_datetime("%Y-%m-%dT%H:%M:%SZ"). 1. (Fill in the blank.) For the edit made by tau, c.timestamp.dt.hour() returns ________, c.timestamp.dt.weekday() returns ________ (Monday is 1 and Sunday is 7), c.timestamp.dt.truncate("1h") returns ________, and c.timestamp.dt.date() returns ________.

3;  2;  2025-02-18 03:00:00;  2025-02-18.

The 18th is eight days after Monday the 10th, so it is a Tuesday. Truncating
to the hour rounds DOWN, discarding the minutes but keeping the date, and the
result is still a datetime. `.dt.date()` drops the time entirely and the
result is a date.

2. (Multiple choice.) A second data source records Ada Kerr's second edit, made on 11 February, as the string "11/02/2025 03:40", with the day written before the month. A classmate parses it with .str.to_datetime("%m/%d/%Y %H:%M"). What comes out?

  1. 2025-02-11 03:40:00, the correct moment, because Polars checks which of the two numbers can be a month.
  2. 2025-11-02 03:40:00, a date nine months later, with no error or warning.
  3. 2025-02-11 15:40:00, because %H reads the hour on a 12-hour clock.
  4. An error, because the string does not match the format.
(B). The format says the first number is the month and the second is the day,
and 11 and 02 are both valid in those roles, so Polars reads 2 November. It
never guesses. (D) is what happens when a number CANNOT fill its role, as in
the next question. The layout `11/02/2025` is ambiguous in a way that
`2025-02-11` is not, which is the argument for the ISO format.

3. (Multiple choice.) The same source records the edit by tau as "18/02/2025 03:05". Which format string parses it correctly?

  1. "%d/%m/%Y %H:%M"
  2. "%m/%d/%Y %H:%M"
  3. "%Y-%m-%d %H:%M"
  4. "%d/%m/%Y %H:%M:%S"
(A). Day, then month, then year, separated by slashes, then hour and minute.
(B) raises an error, since there is no month 18. (C) uses dashes where the
string has slashes, and the literal characters must match. (D) expects seconds
that the string does not contain.

4. (Fill in the blank.) pl.datetime(2025, 2, 11) builds the exact instant of 11 February 2025 at 00:00:00, and pl.date(2025, 2, 11) builds the date alone. The filter c.timestamp > pl.datetime(2025, 2, 11) keeps ________ of the seven edits, the filter c.timestamp.dt.date() > pl.date(2025, 2, 11) keeps ________, and the filter c.timestamp < pl.datetime(2025, 2, 11) keeps ________.

5;  2;  2.

Midnight is an instant, and every edit on the 11th happened after it, so the
first filter keeps the three edits on the 11th plus the 12th and the 18th.
Comparing DATES instead drops the whole of the 11th, leaving the 12th and the
18th. The third filter keeps the two edits on the 10th, which are the only ones
before midnight on the 11th.

(
    revisions
    .with_columns(day = c.timestamp.dt.truncate("1d"))
    .group_by(c.day)
    .agg(n = pl.len())
    .sort(c.day)
)

5. (Fill in the blank.) The output has ________ rows. The busiest day is ________, with ________ edits.

4;  2025-02-11;  3.

Truncating to the day sends every edit to midnight of its own day. Four
distinct days appear: the 10th (2 edits), the 11th (3), the 12th (1), and the
18th (1). Using `.dt.date()` instead of truncating gives the same four counts;
the only difference is that the `day` column is a date rather than a datetime.

6. (Multiple choice.) A classmate replaces .dt.truncate("1d") with .dt.round("1d"), which rounds to the nearest midnight rather than down. Which statement about the rewritten code is correct?

  1. The result is the same, because rounding and truncating agree when the unit is a whole day.
  2. Three edits move to the following day, and the busiest day becomes 2025-02-11 with five edits.
  3. Three edits move to the following day, and that is the better binning, because those edits happened closer to the next midnight.
  4. Rounding sends every edit made after noon to the previous day, so the busiest day becomes 2025-02-10.
(B). Rounding sends every edit made after noon into the NEXT day's bin. Three
edits are after noon: Ada Kerr at 14:20 on the 10th, Bram Vale at 23:30 on the
10th, and Bram Vale at 15:30 on the 12th. They land on the 11th, the 11th, and
the 13th, so the rounded counts are 5 for the 11th, 1 for the 13th, and 1 for
the 18th. Truncation is right for counting per day because an edit at 23:30 on
the 10th happened on the 10th, however late it was.

7. (Fill in the blank.) The code revisions.filter(c.timestamp.dt.weekday() == 2) keeps ________ rows.

4.

The 10th is a Monday, so the 11th and the 18th are Tuesdays, and the 12th is a
Wednesday. Three edits fall on the 11th and one on the 18th.

9. (Multiple choice.) How many rows are returned if the result is followed by .filter(~c.is_reversion), which is meant to keep the edits that are not reversions?

  1. 1
  2. 2
  3. 3
  4. 5
(A). `is_reversion` is null, null, true, false for Ada Kerr and null, null,

The answer you expect, 5, would require the four nulls to be false.

10. (Fill in the blank.) Using the same sort, a third column named since_last is added, the time elapsed since the previous edit to the same page, defined as c.timestamp - c.timestamp.shift(1).over(c.doc_id). The value of since_last for Ada Kerr's second edit is ________, the largest value in the column is ________, and the column contains ________ null values.

13 hours 20 minutes;  6 days 17 hours 50 minutes;  2.

Subtracting two datetimes gives a duration. The gaps are 13h 20m, 5h 35m, and

11. (Multiple choice.) The result is followed by .filter(c.size_diff < 0), to find the edits that made a page smaller. Which rows come back?

  1. Two rows, both edits by rho: Ada Kerr at 02-11 09:15 and Bram Vale at 02-11 01:30.
  2. Three rows: the two above plus Bram Vale's first edit, because a null size_diff counts as less than zero.
  3. Four rows: every edit whose size is below the largest size of its page.
  4. Two rows: Ada Kerr at 02-11 03:40 and Bram Vale at 02-10 23:30, the edits that were later undone.
(A). Only the two -600 rows pass. A comparison against null is null, and
`.filter()` drops null rows rather than keeping them, so the first edit of
each page is excluded, not included. (C) confuses "smaller than the previous
edit" with "smaller than the maximum", and (D) names the edits that were
reverted rather than the edits that did the reverting.

12. (Fill in the blank.) A column next_size = c.size.shift(-1).over(c.doc_id) is added. It contains ________ null values, and its value for Ada Kerr's first edit is ________.

2;  4600.

A negative shift pulls each row's value from the row BELOW it, so the null is
at the bottom of each page rather than the top: the last edit of each page has

The page_views table records the daily views of each page. Note that it stops on the 12th.

views_daily = (
    page_views
    .select(
        c.doc_id,
        moment = pl.date(c.year, c.month, c.day).cast(pl.Datetime),   # midnight of each day
        views = c.views
    )
    .sort(c.moment)

(
    revisions
    .sort(c.timestamp)
    .join_asof(views_daily, left_on="timestamp", right_on="moment",
               by="doc_id", strategy="backward")
)

The "backward" strategy matches each edit to the most recent view record at or before it. Like an ordinary left join, join_asof keeps every row of the left table.

13. (Fill in the blank.) The output has ________ rows. In it, the views value for Ada Kerr's edit at 2025-02-11 03:40 is ________, and the views value for her edit at 2025-02-18 03:05 is ________.

Every edit is kept. The edit at 03:40 on the 11th matches the record for
midnight on the 11th, its own day. There is no record on or after the 13th, so
the edit on the 18th is matched BACKWARD to the last record that exists, 12
February, six days stale, rather than to null. The stale value is
indistinguishable from a real one once it is in the column. The full output:

14. (Multiple choice.) What does the argument by="doc_id" do?

  1. It requires the doc_id values to match exactly before the nearest-in-time search runs, so that each edit is matched to its own page's view counts.
  2. It sorts both tables by doc_id, which join_asof requires before it can run.
  3. It makes doc_id the asof key: each edit is matched to the view record whose doc_id is nearest to its own.
  4. It keeps the doc_id column in the output; without it, the column would be dropped.
(A). The nearest-in-time search runs within each page. Without `by`, an edit
to Bram Vale's page could be matched to Ada Kerr's readership, since both have
a record at the same midnight. This is the same boundary problem that `.over()`
solves for shifts, wearing a different hat.

18. (Multiple choice.) A classmate writes .over([c.doc_id]), dropping c.sid. They get one more bigram than the correct code. Which is it?

  2. 1847 the
  3. Vale Ada
  4. in the
(D). Without `sid`, the shift runs across the sentence boundary, pairing the

19. (Fill in the blank.) For the Ada Kerr page, n_words is ________, n_content is ________, and content_ratio is ________.

12;  5;  0.42.

The twelve alphabetic tokens include five content words: published, Gothic,
novel, novelist, and admired. The four proper nouns are NOT in the list, so the
names do not count, and neither do the determiners or the preposition.
Counting the names gives 9 / 12 = 0.75, which is the tempting wrong answer.

20. (Multiple choice.) A classmate tries to count the tokens on each page with anno.group_by(c.doc_id).agg(n = c.tid.max()). For the Ada Kerr page, this returns:

  1. 15, the correct count.
  2. 9, the number of tokens in the longest sentence.
  3. 6, the tid of the last row.
  4. 2, the number of sentences.
(B). `tid` restarts at 1 in every sentence, so its maximum within a document is
the length of the longest sentence, not the number of tokens. The count wanted
is `pl.len()`, which gives 15. The same restart is why the bigram code groups
by both `doc_id` and `sid`, and why a join on `tid` alone would pair tokens
from different sentences.

21. (Fill in the blank.) Counting only alphabetic tokens, the mean sentence length of the Ada Kerr page is ________ words, and the mean word length, measured in characters of the token column, is ________.

6.0;  4.67.

Sentence 1 has 7 alphabetic tokens and sentence 2 has 5, so the mean is 6.0;
1847 and the periods do not count. Word length uses `token`, not `lemma`:

    Ada 3, Kerr 4, published 9, a 1, Gothic 6, novel 5, in 2,
    The 3, novelist 8, admired 7, Bram 4, Vale 4

    56 characters / 12 tokens = 4.67

Using lemmas instead (publish 7, admire 6) gives 53 / 12 = 4.42, which is the
tempting wrong answer.

22. (Multiple choice.) The type-token ratio of this page, over its twelve alphabetic lemmas, is 12/12 = 1.00. The course computes it for all 75 pages in the corpus, which vary widely in length. A ranking of the pages by type-token ratio is mostly a ranking by:

  1. the richness of each author's own vocabulary.
  2. the share of each page taken up by proper nouns.
  3. page length, with the shortest pages ranked highest.
  4. the number of sentences on each page, with the most sentences ranked highest.
(C). Common words such as "the" repeat sooner the longer a document runs, so
the ratio falls with length. A twelve-token page scores 1.00 regardless of its
vocabulary, and a ten-thousand-token page cannot. (A) is what the ratio is
meant to measure, but on unequal lengths it mostly does not; and in any case it
would describe the prose of the Wikipedia editors, not the author's.

Task E. TF-IDF and Document Vectors

A corpus of four documents. Each has already been lemmatized and filtered to alphabetic tokens, so what you see is what the TF-IDF code sees.

Doc 1:   the  poet   poet   poem
Doc 2:   the  poet   write  novel
Doc 3:   the  novel  sell   well
Doc 4:   the  poem   sell   well

Here tf_norm is a term's count in a document divided by the number of tokens in that document, df is the number of documents containing the term, N is the number of documents, and tfidf = tf_norm × (ln((N + 1) / (df + 1)) + 1).

23. (Fill in the blank.) The term-frequency matrix has one row per document and one column per distinct term, using every term in the corpus. It has ________ rows and ________ columns, the entry for poet in Doc 1 is ________, and ________ of its cells are zero.

4;  7;  2;  13.

The seven terms are the, poet, poem, write, novel, sell, and well:

             the   poet   poem   write   novel   sell   well
    Doc 1      1      2      1       0       0      0      0
    Doc 2      1      1      0       1       1      0      0
    Doc 3      1      0      0       0       1      1      1
    Doc 4      1      0      1       0       0      1      1

Doc 1 has only three distinct terms because `poet` repeats, and the other
three documents have four each, so 15 of the 28 cells are non-zero and 13 are
zero. On the real corpus the zeros are closer to 99% of the matrix.

24. (Fill in the blank.) The TF-IDF score of poet in Doc 1 is ________, of write in Doc 2 is ________, and of the in Doc 1 is ________.

0.755;  0.479;  0.250.

    poet in Doc 1:   tf_norm = 2/4 = 0.5,   df = 2
                     0.5  x (ln(5/3) + 1) = 0.5  x 1.511 = 0.755
    write in Doc 2:  tf_norm = 1/4 = 0.25,  df = 1
                     0.25 x (ln(5/2) + 1) = 0.25 x 1.916 = 0.479
    the in Doc 1:    tf_norm = 0.25,        df = 4
                     0.25 x (ln(5/5) + 1) = 0.25 x 1.000 = 0.250

The trailing +1 keeps `the` from scoring zero even though it is in every
document. Forgetting the repeated `poet` (tf_norm 0.25) gives 0.378, the
tempting wrong answer for the first blank.

25. (Multiple choice.) The filter keeps a term only if the proportion of documents containing it is at least min_df and at most max_df. Which terms survive min_df=0.3, max_df=0.5?

  1. write only.
  2. poet, poem, novel, sell, and well.
  3. None of them.
  4. Every term except write.
(B). `the` (proportion 1.0) exceeds max_df and `write` (0.25) is below min_df.
The other five appear in exactly half the documents, and the boundary is
INCLUSIVE, so they survive. (C) is what you get if you treat the boundary as
strict, and (D) forgets that `the` is in every document.

26. (Fill in the blank.) Take a vocabulary of three terms and three documents with the TF-IDF vectors below. The Euclidean distance between two vectors is the square root of the sum of squared differences.

A = (4, 0, 3)        B = (20, 0, 15)        C = (0, 5, 0)

The Euclidean distance from A to B is ________ and from A to C is ________. By Euclidean distance, A's nearest neighbor is ________.

20;  7.07;  C.

    A to B:  B - A = (16, 0, 12),   sqrt(256 + 0 + 144) = sqrt(400) = 20
    A to C:  A - C = (4, -5, 3),    sqrt(16 + 25 + 9)   = sqrt(50)  = 7.07

Note what this says. B is A multiplied by five: the same terms in the same
proportions, only longer, which is what A's page would look like if someone
expanded it fivefold without changing its subject. C shares not one term with
A. Euclidean distance nonetheless calls B the far one, purely because B's
counts are bigger. That is why length differences swamp vocabulary differences
under Euclidean distance, and why the course uses a length-free measure on
real documents.
